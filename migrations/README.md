# Начальная схема перед первым релизом

9 ноября 2026 года 29 прикладных миграций свёрнуты в 6 начальных блоков. Последняя версия — `m261109_150000_create_site_news`.

| Миграция | Содержимое |
| --- | --- |
| `m261109_100000_create_accounts` | Пользователи, ограничение входа, роли и права аккаунтов/архива |
| `m261109_110000_create_archive` | Профили правил, источники, категории и записи архива, исключения доступности, характеристики |
| `m261109_120000_create_creation_rules` | Определения навыков/черт/предметов/видов/классов, правила предысторий, выдачи и варианты выбора |
| `m261109_130000_create_characters` | Персонажи, базовые характеристики, наборы увеличений и их версии |
| `m261109_140000_create_character_choices_and_sheets` | Выборы персонажа, инвентарь, данные и снимки листа |
| `m261109_150000_create_site_news` | Новости и право управления ими |

Колонки, которые раньше добавлялись отдельными шагами, сразу входят в `createTable`. Категории архива и виды предметов собраны в начальные наборы. Имена таблиц, колонок, ограничений, индексов и значения справочников сохранены. Прикладные миграции не зависят от текущих ActiveRecord-моделей или сервисов приложения.

## Установка в пустую БД

После настройки окружения и установки зависимостей:

```powershell
docker compose exec -T php php yii migrate --interactive=0
```

`config/console.php` подключает `@yii/rbac/migrations` и `@app/migrations`. Yii запускает их в порядке временных меток: сначала 4 системных миграции RBAC из установленной зависимости, затем 6 прикладных. Отдельный запуск RBAC больше не требуется. Пользователи, персонажи, материалы архива и новости из другой БД этой командой не переносятся.

## БД с прежней историей

Новая начальная цепочка предназначена для пустой БД. На БД, где применены старые миграции, **не запускать её повторно**: таблицы уже существуют. Для такой БД нужен однократный переход истории, сохраняющий схему и данные.

1. Сделать резервную копию перед переходом. Проверить `yii migrate/history all --interactive=0`: все 29 прежних прикладных и 4 системных миграции должны быть применены, последняя прикладная — `m261108_231000_create_site_news_table`. Если история неполная, сначала завершить прежнюю цепочку на прежней версии исходников.
2. Сверить фактическую схему с результатом новой цепочки в отдельной пустой БД: колонки/типы/default/NULL, PK/FK/CHECK, индексы, последовательности. Убедиться в наличии требуемых справочников и RBAC. Одна запись о последней версии в истории не доказывает отсутствие ручных изменений схемы.
3. Только при соответствии отметить новую начальную цепочку:

```powershell
docker compose exec -T php php yii migrate/mark m261109_150000_create_site_news
docker compose exec -T php php yii migrate/new --interactive=0
```

`mark` добавляет записи о шести новых версиях в таблицу `migration`, не выполняя `safeUp`. Старые записи истории остаются. Это не способ исправления неполной или отличающейся схемы. Для последующих устройств сравнение и переход выполняются отдельно: их Docker volume не переносится вместе с Git.

**На текущем устройстве переход уже выполнен 9 ноября 2026 года.** Перед отметкой проверены полная старая история, совпадение схемы и неизменность данных всех прикладных и RBAC-таблиц; отметки добавлены в транзакции. `migrate/new` не находит неприменённых миграций.

Старая цепочка доступна в Git до этой свёртки; при незакоммиченной свёртке — в текущем `HEAD`. После перехода существующей БД не откатываться через начальные миграции: их `safeDown` удаляет целые разделы схемы, а старые файлы уже отсутствуют. Для рабочего окружения использовать предусмотренный план обновления и восстановления из [инструкции операций](../docs/operations.md).

## Что проверено

На двух отдельных временных PostgreSQL 17 БД выполнены старая цепочка (4 + 29) и новая (4 + 6). Совпали колонки, их типы/NULL/default, ограничения, индексы, параметры последовательностей, начальные данные и граф RBAC. Из сравнения данных RBAC исключены только служебные `created_at`/`updated_at`, зависящие от времени запуска. Порядок физических колонок не сравнивается: добавленные позднее поля теперь объявлены сразу в таблицах.

На временной БД проверены откат всех 6 прикладных миграций, удаление прикладных прав, повторное применение и переход старой истории через `mark` с сохранением данных. Временные БД удалены. PHP-синтаксис и PSR-12 проверены; для стиля исключены только требования namespace/PascalCase, несовместимые с выбранными стандартными именами миграций Yii.

Эта проверка подтверждает воспроизводимость схемы. Production-развёртывание, восстановление резервной копии и пользовательская приёмка остаются отдельными этапами.

## Дальнейшие изменения

После первого релиза начальную цепочку зафиксировать. Изменения существующей схемы и справочников проводить новыми миграциями с более поздней временной меткой. Не редактировать уже применённый `safeUp` ради изменения production-БД. Оформлять определения колонок по одной на строку, длинные вызовы — по аргументу на строку; `safeDown` строить в обратном порядке зависимостей.
